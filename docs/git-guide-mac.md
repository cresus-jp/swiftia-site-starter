# Git かんたんマニュアル（Mac 編）

**対象**: ターミナルにまだ慣れていないデザイナーさん
**ゴール**: 編集したファイルを GitHub にアップロード（push）して、テスト用サイトに反映できるようになること

> **前提**: アカウント作成・Git のインストール・リポジトリのクローンがまだの方は、先に [GitHub はじめてガイド](github-first-steps.md) を済ませてください。
> Windows をお使いの方は [Git かんたんマニュアル（Windows 編）](git-guide-windows.md) をご覧ください。

---

## 0. このマニュアルでできるようになること

- 作った HTML・CSS・画像をアップロードして、チームと共有する
- アップロードすると**自動でテスト用サイト（`https://案件名.pages.dev`）に反映**されます。FTP ソフトは使いません

覚えるコマンドは実質 **5 つ**だけです（`pull` / `status` / `add` / `commit` / `push`）。初回だけ「名前とメールの登録」（[2 章](#2-自分の名前とメールアドレスを登録する初回だけ)）があります。

---

## 1. まずは「ことば」だけ（3 分）

| ことば | 意味 |
|---|---|
| **リポジトリ** | 案件ごとのファイル置き場。「フォルダ＋変更履歴」のセットだと思ってください |
| **コミット（commit）** | 変更を「セーブ」すること。ゲームのセーブデータのように記録が残るので、失敗しても昔の状態に戻せます |
| **プッシュ（push）** | セーブした内容を GitHub にアップロードすること |
| **プル（pull）** | 逆に、GitHub 上の最新の状態を自分の Mac に取り込むこと |

作業全体の流れはこうなります:

```
自分の Mac で編集 → コミット（セーブ） → プッシュ（アップロード）
                                            ↓ 自動
                          テスト用サイト https://案件名.pages.dev に反映
```

### ターミナルの使い方のコツ

ターミナルは **⌘ + スペース** → 「ターミナル」と入力 → **Enter** で開けます。

- コマンドは**このマニュアルからコピー＆ペーストで OK** です（コピーして、ターミナル上で ⌘+V）
- **1 行貼り付けて Enter** で実行、が基本の操作です
- 実行して**何も表示されずに次の入力待ちになったら「成功」**です（Git は成功したときは静かです）
- 途中でおかしくなったら **control + C** で中断できます。ターミナルを閉じてやり直しても大丈夫です

## 2. 自分の名前とメールアドレスを登録する（初回だけ）

コミット（セーブ）に「誰が変更したか」を記録するための設定です。**最初に 1 回だけ**やれば OK です。

名前とメールアドレスの部分を**自分のものに書き換えて**、1 行ずつ実行してください。メールアドレスは **GitHub に登録したものと同じ**にしてください。

```
git config --global user.name "山田 花子"
```

```
git config --global user.email "hanako@example.com"
```

続けて、「おまじない」を 3 行実行します（日本語ファイル名の文字化け防止と、Mac が勝手に作る不要ファイルをアップロードしないための設定です）:

```
git config --global core.quotepath false
```

```
git config --global core.excludesFile ~/.gitignore_global
```

```
echo .DS_Store >> ~/.gitignore_global
```

登録できたか確認するには:

```
git config --global user.name
```

自分の名前が表示されれば OK です。

## 3. ふだんの作業の流れ（ここだけ覚えれば OK）

毎回、この順番で進めます。

### ① 作業を始める前に、最新の状態を取り込む

エンジニアが同じリポジトリを変更していることがあるので、**編集を始める前に必ず**実行してください。

```
cd ~/Desktop/○○○-site
```

（`○○○-site` は自分の案件のフォルダ名に読み替えてください）

```
git pull
```

（`Already up to date.` と出たら「変更なし」という意味で、それで OK です）

### ② ふつうにファイルを編集する

Finder・エディタで、いつもどおり HTML や CSS を作成・編集してください。ここでは Git のことは忘れて大丈夫です。

### ③ 変更内容を確認する

```
git status
```

赤い文字で表示されるのが「まだセーブしていない変更」です。身に覚えのないファイルが並んでいないか、ざっと眺めてください。

### ④ 変更をぜんぶセーブ対象にする

```
git add -A
```

### ⑤ メッセージを付けてセーブ（コミット）する

```
git commit -m "トップページと会社概要ページを追加"
```

`" "` の中は「何をしたか」がわかる短い日本語で OK です。例:

- `"news 一覧と詳細ページを追加"`
- `"お問い合わせフォームのスマホ表示を調整"`
- `"メインビジュアルの画像を差し替え"`

### ⑥ GitHub にアップロード（プッシュ）する

```
git push
```

これで完了です。**1〜2 分待つと `https://案件名.pages.dev` に自動で反映されます**。ブラウザで確認してください（反映されないときはスーパーリロード: ⌘ + shift + R）。

## 4. うまくいかないとき Q&A

**Q. `git push` したら `rejected` と言われた**
A. 他の人が先に変更をアップロードしています。`git pull` を実行してから、もう一度 `git push` してください。

**Q. `git pull` したら `CONFLICT`（コンフリクト）という表示が出た**
A. 同じファイルを別々に編集してしまった状態です。**自分で直そうとせず、そのまま担当エンジニアに連絡**してください。

**Q. 画面が突然切り替わって `Merge branch ...` のような英文が表示された**
A. 「変更を合体させた記録を残すよ」という確認画面です。**esc キーを押してから `:wq` と入力して Enter** で閉じれば OK です。

**Q. ユーザー名とパスワードを聞かれた（ブラウザが開かない）**
A. Git Credential Manager が入っていません。[GitHub はじめてガイド](github-first-steps.md)の手順③-3 を行ってから、もう一度試してください。

**Q. `Permission denied` や `Repository not found` と言われた**
A. リポジトリへの招待がまだか、招待を承諾していない可能性が高いです。解決しなければ担当者に連絡してください。

**Q. push が `this exceeds GitHub's file size limit` で失敗した**
A. 100MB を超えるファイルは置けません。動画や PSD などの大きいファイルを消してから、担当エンジニアに連絡してください（履歴の掃除が必要になることがあります）。

**Q. 間違えて大事なファイルを消してしまった／変な状態になった**
A. あわてなくて大丈夫です。コミットの履歴が残っているので、たいてい元に戻せます。**自分でいろいろ試す前に**担当エンジニアに相談してください。

## 5. やってはいけないこと

- **`functions/` フォルダ・`_routes.json`・`.github/` フォルダを編集・削除しない**（サイトの公開・SEO の仕組みが壊れます。リポジトリに最初から入っているファイルは「触らないもの」と考えてください）
- **`sitemap.xml` や `robots.txt` を自分で作って置かない**（システムが自動配信しています。ファイルを置くとそちらが優先されて自動配信が止まります）
- **100MB を超えるファイル、PSD・AI・動画などの元データを入れない**（納品物は書き出した HTML/CSS/JS/画像だけ）
- **このマニュアルにないコマンドを実行しない**（特に `--force` が付くもの。ネット記事のコマンドを試す前に、まず担当エンジニアに相談してください）

## 6. コマンド早見表

| やりたいこと | コマンド |
|---|---|
| 案件フォルダに移動 | `cd ~/Desktop/○○○-site` |
| 最新を取り込む（作業前に必ず） | `git pull` |
| 変更の確認 | `git status` |
| 変更をセーブ対象にする | `git add -A` |
| セーブする | `git commit -m "やったことを書く"` |
| アップロードする | `git push` |

> **補足（エンジニア向け）**: SSH での clone/push に慣れている場合はそちらでも問題ありません。本マニュアルは初学者向けに HTTPS + Git Credential Manager（ブラウザ認証）に統一しています。
